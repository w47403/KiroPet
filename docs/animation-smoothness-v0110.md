# v0.11.0 动画稳定性

本次覆盖 manifest 中全部 21 段动作。原图位移与播放时间线分别处理，构建保留原始绘图，安装后的桌宠不需要图像库或模型。

## 已定位的原因

原图按精灵图的网格切出后，不同格子的角色坐标、比例和实际脚底并不一致。部分近透明邻格残片还使 alpha 外框误报脚底位置。sleep/nap 后四张的主体比前四张上移约 43–45px；sit_down 中间帧在坐下途中先过度下蹲再反弹。工作/编辑交替使用另一张独立绘制的 work_bridge，增加了脸部位置和角色比例差异。

播放器还有独立问题：工作和编辑切换清零循环时钟，工具状态覆盖原相位，提前结束互动没有补偿背景暂停时间，WPF 拖拽覆盖了睡眠计时。

## 素材处理

`scripts/animation-registration.json` 为每张原画记录基线、缩放和局部头部修正。站立、坐姿、侧躺采用各自的姿态约束，走路、拖拽、伸懒腰和侧躺过程保留原本的位移。少量已目检的邻格残片有显式删除矩形，避免全局阈值误删爱心、运动符号或外部手。

配准后，nap/sleep 的主体基线摆幅由 45px 降到 0；sit_down 由 15px 降到 0；stretch 由 27px 降到 0；rice_full 由 23px 降到 0。坐下过渡末帧与坐姿首帧的顶部差由 14px 降到约 2px。基线一致不等于所有角色部位都固定，表情和姿态变化仍保留。

`scripts/smooth_animation_assets.py` 在离线构建中生成运动帧。长停留保持静止，发生动作的区间以不超过 40ms 的步长编排。开场、收尾和拥抱采用共同端点，工作/编辑去掉不匹配的 work_bridge 交替。桌沿和桌腿保持相同像素。

## 播放与资源

三端共享 manifest 时长、原画来源和相同的状态相位规则。工作/编辑按归一化相位切换，工具结束恢复之前的打字相位；取消互动和结束拖拽均补偿背景时间。开场和收尾根据当前片段及任务时钟保护，不能因补帧的来源姿态是 idle 而被摸头打断。

WPF 按实际显示高度预解码，调整尺寸后重建缓存；探头单独从高清原画裁切。Tk 使用 140/190px 的预缩放帧。VSIX 只收录 manifest 引用资源，构建库、原始精灵图和对比快照留在开发环境。

## 复核

`npm run verify -- --browser --tk` 执行完整回归、打包、三端帧边界与原生窗口检查。

`python scripts/build_smoothness_preview.py` 生成 `output/animation-v0110/review.html`，对比固定的旧版快照与当前素材；支持全部动作、同毫秒播放、140px 实际尺寸、逐帧与慢速。旧版快照保存在 output，未作为运行资源发布。基线测量与程序测试不能代替对大动作遮挡、轮廓和跨姿态衔接的目检。
